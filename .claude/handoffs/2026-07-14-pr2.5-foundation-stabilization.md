**Status:** Complete (2026-07-14); PR 3 prerequisites satisfied

## Objective

Close the correctness, artifact-integrity, identity, packaging, security, and
state-documentation gaps found after PR 2. This PR must make the Silver
foundation safe to extend; it must not implement Gold generation.

## Why this PR blocks Gold

The current experiment path does not consistently propagate dataset task,
metric, seed, folds, and settings into methods. Artifact manifests do not bind
themselves to a layer, Silver carries a broad case fingerprint instead of a
stage identity, dependency groups disagree with their documentation, and the
repository security audit currently fails on `setuptools==81.0.0`.

Building Gold on these assumptions would harden incorrect reuse and execution
contracts.

## Scope

### 1. Resolve per-case execution configuration

- Add a typed context for one case, provisionally `CaseExecutionContext`.
- Resolve dataset task from validated dataset metadata/request rather than only
  the process-wide `Settings.task`.
- Resolve a compatible default metric per task, while preserving an explicit
  user metric override.
- Carry seed, CV folds, evaluation config, resource settings, artifact/run
  identity, and execution profile in the context.
- Pass the same resolved evaluator/settings into the method adapter and outer
  evaluation.
- Reject incompatible task/metric pairs before method or provider creation.
- Ensure a matrix can contain classification and regression cases in the same
  platform invocation.

### 2. Define layer-specific fingerprints

- Add named/versioned Bronze, Silver, Gold-input, and Platinum-input identity
  helpers or contracts.
- Make Silver reuse depend on the Silver fingerprint, not the full case
  fingerprint.
- Keep the case fingerprint as an aggregate run identity only.
- Add invalidation matrix tests: model/metric changes reuse Silver; prompt or
  method changes invalidate Gold; evaluation changes invalidate Platinum only.
- Document which configuration fields belong to each identity.

### 3. Strengthen package integrity

- Add `layer` to `RunManifest` and validate it against the namespace/reference.
- Add package-kind or contract identity where needed to distinguish Bronze,
  Silver, Gold, and Platinum manifests of the same schema version.
- Require resolved artifacts to be declared in the manifest.
- Verify size/hash before returning an artifact from the safe read path.
- Make loaders enforce their exact required artifact set, media types, schema
  versions, and descriptor layers.
- Add negative tests for wrong-layer manifests, undeclared files, optional vs
  required corruption, missing `_SUCCESS`, future schemas, and path traversal.

### 4. Correct optional dependency groups

- Remove Hamilton/DuckDB from `observability`.
- Keep them in `pipeline`.
- Decide explicitly whether aggregate `all` includes `pipeline`; update code,
  lockfile, docs, and tests consistently.
- Confirm importing legacy `feature_forge` does not require Hamilton.

### 5. Restore security gate

- Upgrade or constrain the dependency chain so supported environments resolve
  a fixed `setuptools>=83.0.0` where applicable.
- Regenerate `uv.lock` with `uv`.
- Run the repository audit without adding a permanent blanket allowlist.
- Retain the separately documented optional Torch advisory only if it remains
  unfixed and isolated from default/pipeline environments.

### 6. Refresh repository truth

- Reconcile `.planning/STATE.md` with the live checkout.
- Remove or mark resolved the stale `AgentMemory` and default-registry issues.
- Record the current dependency audit state.
- Separate open bugs, accepted risks, planned work, and quality debt.

## Completion report

### Contracts delivered

- `CaseExecutionContext` resolves one dataset-owned task, compatible metric,
  seed, folds, evaluation/resource settings, shared `CVEvaluator`, run/case
  identity, artifact policy, and execution profile before method/provider
  construction.
- `ExperimentalPlatform.run(metric=...)` is the explicit metric override.
  Otherwise a compatible configured metric is retained and an incompatible
  global default becomes the task default (`auc` or `r2`). Explicit
  incompatible built-in pairs fail before method construction.
- Identity schema `1` defines Bronze, Silver, Gold-input, and Platinum-input
  helpers. Silver reuse compares `layer_fingerprint`; `case_fingerprint` is
  aggregate orchestration identity only.
- `RunManifest` schema `1` now requires `layer`, matching `package_kind`, and
  `layer_fingerprint`. Pre-PR-2.5 manifests without these fields must be
  regenerated rather than silently reused.
- Safe `resolve()` accepts only declared artifacts and verifies size/hash.
  Silver replay enforces exact Bronze/Silver required files, media types,
  schema versions, and layers.
- `_SUCCESS` contains the commit-time manifest SHA-256. Verification,
  namespace lookup, and safe resolution use that anchor rather than trusting a
  digest recomputed from a potentially modified manifest.
- Existing Bronze/Silver namespace reuse requires verified package integrity,
  matching layer, and matching layer fingerprint. Request-only differences
  such as physical source policy or aggregate case identity do not invalidate
  the logical Silver layer.

### Dependency and security outcome

- `observability` excludes Hamilton/DuckDB; `pipeline` owns both; aggregate
  `all` includes both. Legacy import succeeds in an isolated no-extra install.
- `uv.lock` resolves `setuptools==83.0.0`.
- Isolated default and pipeline audits: `No known vulnerabilities found`.

- Aggregate `all` retains accepted optional Torch risk: `torch==2.10.0`
